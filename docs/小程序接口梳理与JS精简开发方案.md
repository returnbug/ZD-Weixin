## 1. 目标与边界

根据 Weixin 当前调用方式和 YZ 后端的实际参数、返回结构，精简小程序接口层及相关页面 JS，减少重复封装，提高可读性，并在必要位置添加中文注释。

实施必须遵守以下约束：

- 只修改 Weixin 小程序端，YZ 仅作为接口定义的阅读依据。
- 不读取、不修改 `uni_modules`、`unpackage` 下的内容。
- 不改页面模板、样式、布局、文案、路由和图表外观。
- 不改变已有功能、权限范围、业务统计口径、筛选规则、分页规则和异常兜底。
- 不引入新依赖、状态管理库、请求类、接口注册器或通用分页框架。
- 不运行测试、构建、lint、类型检查、模拟器或接口联调；本文结论来自源码阅读，不代表运行验证结果。
- 文档获确认前，不实施以下代码方案。第 7 节所列字段差异也不默认纳入修改。

## 2. 项目调用结构

当前调用链为：

```text
pages 中的页面脚本
  → api/index.js 导出的业务接口
  → api/modules 下的 user、home、station、device、alarm
  → api/base.js 的统一请求
  → YZ/GG/API 或 YZ/GF/API
```

| 服务 | 小程序当前配置 | 后端路由入口 | 用途 |
| --- | --- | --- | --- |
| 公共平台 GG | `https://gg.thezd.cn` | [GG 路由](../../YZ/GG/API/Web_APP/urls.py) | 登录、公共权限、应用模块 |
| 光伏业务 GF | `https://gf.thezd.cn` | [GF 路由](../../YZ/GF/API/Web_APP/urls.py) | 新能源权限、首页、电站、设备、报警 |

当前业务页面均位于 `pages/gf`。此次接口对应关系落在 GG 和 GF，不需要修改 YZ 中的 NY、ZD 等其他服务。

### 2.1 请求约定

- 下文列出的现有远程调用均使用 **POST**。
- 后端主要通过 `request.POST` 读取中文参数名；当前小程序通过 `multipart/form-data` 提交，不能直接改为 JSON 请求体。
- 数组、对象类型的表单值会序列化为 JSON；`undefined`、`null` 被跳过，空字符串仍会提交。
- 请求超时为 `150000ms`，本次保持不变。
- `统一请求` 目前自动拆一层小写 `data`，保留中文 `数据`、`结果` 和 `form` 等业务结构。
- HTTP/网络错误提示保持原样；登录接口自己的 `状态`、`提示` 判断也保持原样，不借重构统一修改业务成功判定。
- `Authorization` 拼装、本地 7 天登录有效期和现有 token 兼容行为保持原样。

## 4. 请求参数及数据转换约定

### 4.1 列表参数

`gf加载数据`、`nbq加载数据`、`db加载数据`、`bj加载数据` 共同读取：

| 参数 | 现有用途与默认行为 |
| --- | --- |
| `文件` | 电站默认 `光伏`；设备默认 `设备列表`；报警默认 `报警日志` |
| `显条` | API 层电站/报警默认 50，设备默认 100；当前电站页面明确传 10，报警页面传 50，设备页面传 100 |

| `模式` | 当前页面使用 `查询`；后端还有 `导出` 分支，本次不新增导出功能 |
| `树选` | 默认空字符串，必须保留字段提交 |
| `条件` | 默认空字符串，必须保留字段提交 |
| `可见` | 调用方显式传入时原样使用；否则读取当前区域类型对应的权限缓存 |
| `区域类型` | 标准值为 `区域1`、`区域2`、`区域3`；现有默认值为 `区域1` |

各业务额外参数：

| 业务 | 额外参数及当前默认值 |
| --- | --- |
| 电站 | `系统类型=光伏`、`通讯状态=全部状态`、`报警状态=全部状态` |
| 设备 | `系统类型=全部类型`、`设备类型=当前选择类型`、`设备模版=全部模版`、`通讯状态=全部状态`、`报警状态=全部状态` |
| 报警 | `系统类型=全部类型`、`设备类型=全部类型`、`设备模版=全部模版`、`报警类型=全部类型`、`恢复状态=全部状态` |

`可见` 是后端要求的区域范围表达式字符串，不在前端擅自改成数组、重新拼接格式或省略。后端使用它限制数据范围。

### 4.2 首页与电站看板

- 首页 `日期类型` 继续由页面映射：页面“日”传 `月`，“月”传 `年`，“年”传 `总`，用于查看每日、每月、每年的趋势点。不能因字面不同改为直接透传。
- `gf读取` 使用电站列表返回的 `ID`；周期为 `日/月/年/总`。
- 电站详情现有日期精度继续保留：日为 `YYYY-MM-DD`，月为 `YYYY-MM`，年为 `YYYY`，总维度仍按原页面传当前完整日期。
- `gf读取` 返回的业务对象位于小写 `form` 中，不能混用设备接口的中文 `表单`。

### 4.3 列表字段映射

```text
加载字段返回：字段[列索引].名称
加载数据返回：数据[行索引][列索引]
接口层转换：行对象[字段名] = 行[列索引]
页面使用：标准化后的电站、设备、报警对象
```

实施时保留以下规则：

- 保留“先取得列定义再映射二维数组”的结构；不能根据页面目前显示的几个字段硬编码完整列顺序。
- `显示=0` 的字段仍可能包含 `ID`、电站 ID 等后续逻辑需要的数据，不能在映射前过滤隐藏列。
- 设备模版和区域属性会影响列名称，设备动态字段解析仍有实际用途。
- 列名、显示标记及原有空值处理按现有逻辑保留；本次不顺便调整空列筛选规则。
- 页面使用的 `id`、`_key`、`名称`、`当日发电量`、`展示字段` 等派生字段继续由接口层提供。

### 4.4 设备详情与设备日志

`sb读取` 的数据来自设备保存的表单、基本信息和表格配置，后端会将实时单元格替换为包含 `数据ID`、`值`、`时间` 的对象。因此下列处理必须保留：

- JSON 字符串转对象/数组。
- 基本信息中的“字段名行 + 字段值行”配对。
- 表格的 `列名称列表`、`行名称列表`、`单元格数据` 解析。
- 从单元格对象中读取 `值`，以及原有 `--` 占位规则。
- 原有报警表格排除规则与页面隐藏字段规则。

`BJ设备日志` 按 `通讯异常`、`逆变器报警` 分组返回。需先使用完整字段定义映射每行，再生成可见展示字段，不能因隐藏 ID 列而造成列值错位；也不能将该接口擅自扩展为历史日志查询。

## 5. 已确认的 JS 精简方案

本节保留用户已确认的开发方案，具体完成内容见第 9 节。在现有文件内减少重复代码，保持对页面的接口方法、参数和返回结构不变。

### 5.1 `api/base.js`：复用少量重复逻辑

| 现状 | 拟修改 | 必须保留 |
| --- | --- | --- |
| 多个模块重复实现参数排序后序列化 | 提取一个用于扁平请求参数的缓存键函数 | 原先已排序的键保持相同语义；不在本次扩展为深度对象序列化框架 |
| 各模块重复检查、保存、清理进行中的 Promise | 提取一个简短的在途请求复用函数，由调用方提供自己的缓存对象和请求函数 | 成功/失败后均释放；旧请求完成时不能删除同键的新请求 |
| 各模块重复缓存过期读取及清空逻辑 | 提取简单内存缓存读取、清空函数 | 30 分钟有效期、各模块缓存范围、会话隔离不变 |
| 电站和报警重复解析同一种下拉选项 | 复用一份下拉文本列表转换 | 电站去重；报警补齐“全部类型”等默认项；各自返回结构不变 |
| HTTP 非成功和业务非成功分支的提示、reject 代码相同 | 合并重复错误分支 | 判定条件、短路顺序、提示内容不变 |

这些辅助函数只负责重复的机械处理，不接管业务权限、不自动改变缓存策略、不自动缓存所有请求。`统一请求` 的表单构造、超时、登录态、错误处理不重写。

### 5.2 `api/modules/home.js`：固定字段直接读取

- 对已确认只有一个固定名称的首页数据字段，移除“单元素字段数组 → 通用字段查询”的额外跳转。
- 数值转换函数直接接收数值，不为了复用字段查询临时创建 `{ 数值: ... }` 对象。
- 使用第 5.1 节的简单工具替代重复的请求缓存维护代码。
- 保留应用字典转数组、应用可见性过滤所需数据、30 分钟模块缓存及首页下拉缓存。
- 保留首页核心指标先渲染、趋势图后更新的流程及当前数据兜底。
- 保留原始接口方法和页面数据转换方法，不为了缩短文件而删除已导出的方法。

### 5.3 `api/modules/station.js`：合并字段缓存、缩短取值链路

- 将同一区域下的“字段原始响应缓存”和“已解析字段列表缓存”合为一条缓存记录，共用过期时间。
- 使用现有通用区域函数，删除仅转发到同一默认值 `区域1` 的包装函数。
- 二维数组完成映射后，直接读取 `电站名称`、`通讯状态`、`日满发小时` 等实际列名，删除逐层转发的取值函数。
- 参数构造已经明确挑选后端需要的字段，可去掉“复制参数对象，再删除前端辅助字段”的重复步骤。
- 电站图片仍通过 GF 静态资源 `static/tp/` 拼接，保持现有不追加时间戳的行为。
- 保留 `gf加载数据` 返回对象数组、`gf读取` 返回 `form` 的约定，以及现有异常返回和分页标识规则。

### 5.4 `api/modules/alarm.js`：按实际列名转换

- 将字段响应和字段列表合为同一缓存记录，保留会话隔离与 30 分钟有效期。
- 将 `['日志内容']`、`['设备信息']` 等单字段常量及通用查询改为直接属性读取；保留文本清理和空值规则。
- 后端的 `模版名称` 继续映射到页面使用的 `模板名称`；`所属电站`、`开始时间`、`结束时间` 等映射保持不变。

### 9.2 缓存与接口约定的落实

- 公共函数只处理缓存键、有效期读取、清空和在途 Promise 复用。缓存对象、会话判断、结果写入仍由各模块管理，没有引入全局业务缓存框架。
- 电站和报警字段缓存统一为 `{ data: { 响应数据, 字段列表 }, time }`，原始响应与字段顺序共用一个过期时间。
- 设备字段缓存只保存原始响应；`获取设备列表` 仍取得字段后再解析、请求列表，并返回原有 `{ 字段, 数据, 条数 }`。
- 电站字段为空时仍不写入字段结果缓存；报警、设备字段缓存及其他空值处理沿用原有约定。
- 首页、电站、报警的下拉缓存仍各自管理，没有跨模块合并或改变刷新时机；首页原本的本地缓存继续保留。
- 原先按键名排序的请求缓存继续排序；电站下拉和电站列表原先直接 `JSON.stringify` 的键保持原样。
- 在途请求无论成功还是失败都会释放；清理前比较 Promise 引用，避免旧请求删除会话切换后建立的新请求。
- 各模块对旧会话响应的结果缓存写入限制继续保留；30 分钟静态有效期、实时接口不缓存结果的策略不变。
- `api/index.js` 及业务接口原有导出未删除；没有新增远程接口、请求依赖、页面功能或持久化缓存键。
